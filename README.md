# EatSoon (잇순) — Lean MVP Prototype

자취 대학생의 식재료 폐기를 막는 최소 기능 웹앱.
`기말프로젝트 초안.pdf`의 가설 검증용 MVP를 그대로 구현했습니다.

> 핵심 가설 — "소비기한이 임박한 식재료를 **적시에 알리고**, **간단한 활용법**까지 제공하면
> 소비 전환율 70% 이상을 달성할 수 있다."

---

## 실행 방법

빌드 도구가 필요 없습니다. `index.html`을 브라우저로 열면 바로 동작합니다.

로컬 서버로 열려면 (알림 권한 등 일부 브라우저 기능은 `http://`에서만 동작):

```bash
python -m http.server 5173
```

이후 `http://localhost:5173` 접속. 모바일 화면 기준으로 설계되어 있으니
개발자도구의 모바일 뷰(375px)로 보면 실제 사용 경험과 가장 가깝습니다.

## PDF ↔ 구현 매핑

| PDF 항목 | 구현 |
|---|---|
| STEP 01. REGISTER (최소 정보 등록) | `#/add` — 식재료명 + 소비기한 **2개 필드만**. 자주 쓰는 재료/기한 퀵칩 제공 |
| STEP 02. REMIND (D-2 · D-Day 알림) | 앱 진입 시 D-2 이내 재료를 자동 감지 → 상단 푸시 배너 + 브라우저 알림. 홈의 `알림 테스트` 버튼으로 재발송 |
| STEP 03. RECOMMEND (원클릭 레시피) | 보유 재료 매칭 레시피 **기본 30종** (프렌치토스트 · 원팬 크림파스타 · 김치찌개 · 카레라이스 등), 소요 3~15분. **남은 재료 기반 추천** + **내 레시피 직접 추가** |
| STEP 04. CONSUME (KPI 측정 버튼) | 모든 재료 카드와 레시피 시트에 **[먹었어요 / 버렸어요]** |
| 10. KPI FRAMEWORK | `#/stats` — 소비율(≥70%) / 알림 확인율(≥80%) / 레시피 열람률(≥60%) / 등록 완료율(≥85%) + 가설 충족·미달 판정 |
| 09. VALIDATION (Telemetry) | 원시 이벤트 로그 최근 30건 표시. 사용자 테스트 시 Drop-off 지점 추적용 |

### KPI 산식

| 지표 | 산식 |
|---|---|
| 임박 식재료 소비율 | `[먹었어요] 수 ÷ D-Day 도달 식재료 수` (먹음 + 버림 + 기한 경과 미처리) |
| 알림 확인율 | `알림 확인 ÷ 알림 발송` |
| 레시피 열람/선택률 | `레시피 상세 열람 ÷ 레시피 목록 조회` |
| 등록 완료율 | `등록 완료 ÷ 등록 화면 진입` |

## 레시피 추천이 동작하는 방식

냉장고에 남은 재료로 만들 수 있는 요리를 점수순으로 보여주고, 고르면 그 요리의 보편적인
조리법(재료 계량 + 순서)이 나옵니다. 홈 화면에는 상위 3개, 레시피 탭에는 상위 6개가 뜹니다.

**점수 계산** (`scoreRecipes` in `app.js`)

| 요소 | 가중치 |
|---|---|
| 보유 재료를 쓰는 개수 | ×10 |
| **임박(D-2 이내) 재료**를 쓰는 개수 | ×25 — 버려질 재료를 우선 소진 |
| 재료 충족률 (보유 ÷ 전체) | ×20 |
| 부족한 재료 개수 | −4 |
| 조리 시간 | −0.2/분 |

- 카드에 `보유 재료 n개 사용`, `부족: OO`을 함께 표시해 장을 더 봐야 하는지 바로 판단할 수 있습니다.
- 부족한 재료가 없으면 **"바로 만들 수 있어요"** 배지가 붙습니다.
- 등록명이 달라도 매칭됩니다 — `SYNONYMS`에서 처리 (달걀↔계란, 빵↔식빵, 삼겹살↔돼지고기, 오뎅↔어묵 등).

## 내 레시피 추가

레시피 탭 → `+ 내 레시피 추가`. 요리명 · 소요 시간 · 재료(한 줄에 하나) · 만드는 법(한 줄에 한 단계)만
입력하면 됩니다.

- 재료 줄에서 **표준 재료명을 자동 추출**해서(`INGREDIENT_VOCAB`) 추천 엔진에 그대로 반영됩니다.
  예: `계란 2개` → 태그 `계란`. 사전에 없는 재료는 첫 단어를 태그로 씁니다.
- 이모지는 요리명/재료에서 자동으로 고릅니다.
- 저장한 레시피는 `내 레시피` 배지가 붙고, 필터 칩과 상세 화면에서 수정·삭제할 수 있습니다.
- 기본 레시피와 똑같이 남은 재료 추천 대상에 포함됩니다.

## 정적 배포

빌드 과정이 없어서 폴더를 그대로 올리면 됩니다. 어느 쪽이든 무료입니다.

**GitHub Pages**

```bash
git init && git add . && git commit -m "EatSoon MVP"
```

이후 GitHub에 저장소를 만들어 push하고, Settings → Pages → Source를 `main` 브랜치 루트로 지정하면
`https://<아이디>.github.io/<저장소명>/` 으로 공개됩니다.

**Netlify / Vercel** — 이 폴더를 드래그앤드롭하거나 저장소를 연결하면 끝입니다.
빌드 명령은 비워두고 출력 디렉터리만 루트(`.`)로 두면 됩니다.

배포해도 데이터는 **접속한 사람의 브라우저에만** 저장됩니다. 서버가 없으므로 여러 사용자의
KPI를 한곳에 모으려면 별도의 백엔드가 필요합니다(이번 MVP 범위 밖).

## 구조

```
index.html    화면 4개(냉장고 / 등록 / 레시피 / 검증 지표) + 시트 · 배너
styles.css    DESIGN.md 토큰 시스템 (색/타이포/여백/라운드/그림자)
recipes.js    기본 레시피 30종 + 동의어/재료 사전 + 이모지 매핑
app.js        상태·라우팅·알림·추천 엔진·내 레시피·KPI 집계
```

## 디자인

`DESIGN.md`(Apple-design-analysis)를 토큰 단위로 적용했습니다.

- 인터랙션 색은 **Action Blue `#0066cc` 단 하나**. 두 번째 강조색 없음
- 전면 타일(흰색 ↔ 파치먼트 ↔ 근검정)을 번갈아 쌓아 **색 변화 자체를 섹션 구분선**으로 사용
- 헤드라인은 음수 자간, 본문은 17px/1.47 고정
- 그림자는 **제품 이미지 1개에만** (`rgba(0,0,0,.22) 3px 5px 30px`) — 카드·버튼·텍스트에는 금지
- 버튼 문법 2종: 파란 pill CTA + 유틸리티 사각 버튼
- 모든 터치 영역 44×44px 이상

## 데이터

모든 데이터(식재료 · 내 레시피 · 검증 이벤트)는 브라우저 `localStorage`(`eatsoon.v1`)에만 저장되며 서버로 전송되지 않습니다.
상단 `데이터 초기화`로 전체 삭제, 빈 상태의 `데모 데이터 넣기`로 테스트용 재료 6개를 넣을 수 있습니다.

### 알려진 제약 (프로토타입 범위)

- 브라우저 알림은 앱이 열려 있을 때만 발송됩니다. 앱을 닫은 상태의 실제 푸시는
  Service Worker + Web Push 서버가 필요하며, PDF의 Out of Scope 원칙에 따라 제외했습니다.
- 레시피는 정적 데이터셋이며 AI 개인화(Next Step)는 미포함입니다.
